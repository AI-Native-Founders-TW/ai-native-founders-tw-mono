# Specs

本目錄的內容定義與分層原則依 [FORMULATION](../FORMULATION.md)。下表提供目前各 package 的入口。

| Package | 範圍 |
|---|---|
| [願景和問題](00-願景和問題/README.md) | 願景、組織問題與創辦人的話 |
| [制度](01-制度/README.md) | 憲法、憲政問題與共同制度 |
| [R&R](02-R&R/README.md) | 各項 Role 的職責 |
| [SOP](03-SOP/README.md) | 成員可直接使用的操作步驟 |
| [Web](04-Web/README.md) | 各 Web channel 的文案與規格，目前 landing page 位於其 subpackage |
| [社群基建](05-社群基建/README.md) | Discord、GitHub 等平台的設定與權限規格 |

## 文件命名

問題、原則、機制與功能分別使用 `[問題]`、`[原則]`、`[機制]`、`[功能]` 前綴。Role 使用 `[Role]`，SOP 使用 `[SOP]`，平台規格使用 `[規格]`，文案使用 `[文案]`。混合內容依主要責任命名，不為套用前綴拆成多檔；既有願景、憲法與 README 沿用其名稱。

## 制度與執行入口

憲法與共同制度見制度 package；Role 定義職責與決策範圍，現任人員見 [members assignment](../members/r-and-r-assignment.md)。成員行使權利的步驟見 [憲政 SOP](03-SOP/憲政/README.md)。修憲文書、逐條原文與修訂內容的要求依[修憲及正式成員監督](<01-制度/[機制] 憲政制度.md#修憲及正式成員監督>)與[修改共同制度或提出修憲 SOP](<03-SOP/憲政/[SOP]修改共同制度或提出修憲SOP.md>)；獨立憲法檢查依 [AGENTS](../AGENTS.md#憲法)，不在入口重訂規則。
