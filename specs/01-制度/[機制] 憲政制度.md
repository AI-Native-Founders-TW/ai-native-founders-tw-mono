# 憲政制度

本制度集中定義正式成員、R&R、Council、共同決定、罷免、修憲與權限交接，回應[憲政制度的問題](./[問題]%20憲政制度.md)。[憲法](憲法.md)維持獨立，規定組織目的、基本原則與規範效力；本制度不得以共同決定或搬移文件豁免憲法。

本文件為組織的共同運作規則。憲法規定治理權及保護範圍，本文件定義資格、案件、職位與操作如何接續。制度採納、首屆任命、個案投票及平台操作是不同事件；實際成立依據及未完成驗證由 [Kickoff](../../plans/001-Kickoff/plan.md)追蹤，不因文字更新就產生人員任職或平台權限。

申請與成員參與的共同規則集中於本文件。各 [R&R](<../02-R&R/README.md>)維護自己的職責、routine、non-routine 及所需權限配置；SOP 維護操作步驟與 comments，不另定共同權力或門檻。

## 申請與成員資格

一般申請以 PR 提交自介；自介依本制度審查通過時，即取得正式成員資格。首屆任命與有效退出後的恢復，分別依「首屆任命與生效」及「長期不參與與成員資格處理」，不要求以一般審查重做已有效成立的資格。

提交自介 PR 表示提出申請，不等於審查已通過。GitHub Organization Member、Discord 身分與本組織成員資格不自行視為同一件事；Discord 邀請不是入會門檻。

## 自介內容與提交位置

自我介紹放在公開 GitHub Repo 的 members 資料夾。編號、帳號唯一性與資料對應依[成員識別與資料](<[規格]成員識別與資料.md>)；配置編號不取代資格決定。自介寫出自己是誰、想 share 的東西，以及自己的 Contributions：可以幫什麼忙、想要幫什麼忙。

每個人都要在自介附上一張本人的真人照片。照片放在 `members/assets/`，並由自介以相對連結引用。

自介可參考 [members 的自介範例與 PR 提交說明](../../members/README.md)，格式可自由調整。

自介內容提供協作資訊，不代表申請者或成員已承諾接受任何指定工作。R&R assignment 與 Contributions 分開，依[成員參與制度](#rr-assignment)記錄在獨立表格；成員、自介連結與個人 R&Rs 由 [members 總表](../../members/members.md)提供入口。

## 自介審查

審查依[憲法第 4 條（開放與成員資格）](憲法.md#第-4-條開放與成員資格)。

自介的審查看內容有沒有真誠，不看文章品質。自介由 AI 寫，是很正常的。

自介很真誠，所以值得信任，但沒有經歷、沒有專案的人，可以加入。

自介的審查與開放心態並存：開放心態講的是背景，審查看的是有沒有真誠。基本參與度義務依[本制度的基本參與度義務](#基本參與度義務)。


## 基本參與度義務

成員須保有參與意願，得以交流、學習、協作或回覆願意繼續參與表示；不要求一定要幫忙。長期無可確認參與或回覆時，只依本制度的通知、清查與恢復程序處理，不以「潛水」作主觀除名理由。

成員可按照自己的方式貢獻，依[憲法第 5 條（自願貢獻與參與義務）](憲法.md#第-5-條自願貢獻與參與義務)。本制度沒有新增每週發言、開會次數或活動出席要求。

## R&R assignment

自介的 Contributions 寫可以幫什麼忙、想要幫什麼忙。R&R（Role and Responsibility）的 assignment 獨立記錄，不以自介中的能力或意願直接推定已接受某項工作。

| 對象 | 規定 |
|---|---|
| 每個 R&R | 設一位 Leader，並記錄自行加入的 Contributors。 |
| Leader | 負責該 R&R 的決策，不必獨自完成全部工作；由本人確認承擔，不替其他人指定工作。 |
| Contributors | 成員自行選擇加入的 R&R；每位成員至少選一個，可選一個或多個（1..*）。 |
| 同一人的兩種身分 | Leader 也須至少選一個 R&R 當 Contributors，可以是自己擔任 Leader 的同一個 R&R。 |

選擇 R&R 表達參與方向，不等於接受該範圍內的每一項工作。具體工作仍由本人依意願認領，不因 assignment 強制承擔工作，也不增加時數、產出量或出席要求。

各項分工的責任範圍由 [R&R package](<../02-R&R/README.md>)維護；[R&R assignment 表](../../members/r-and-r-assignment.md)維護 Leader 與 Contributors；[members 總表](../../members/members.md)維護所有成員、自介連結及其 R&Rs 索引。每次 assignment 變更須在同一個 PR 更新兩表，讓按人與按分工查找得到相同結果；成員調整 Contributors 時仍須至少保留一個 R&R。

Leader 尚未確認的 R&R 明列待確認；不得把它當成已完成決策分工。尚未有人接受前，不由 AI 或資料維護者代指派，也不以該 R&R 名義作出決定。Leader 的更換需記錄接任者本人的確認；尚未接任時如實標示待確認，不延續已不成立的 assignment。

申請者可在自介 PR 一併提出自己的 Contributors 選擇，但應標示申請中；審查通過後才列入成員。自介審查、組織成員資格及平台管理權依本制度各章與 R&R 權限配置，不因成為 Leader 或 Contributors 就取得所有權限；Leader 與 Council 的關係依「Council 與 R&R」。

## Routine 與 non-routine responsibilities

每項 R&R 的責任定義放在 [R&R package](<../02-R&R/README.md>)，一項一份文件；assignment 維護人員，members 總表提供按人索引。各 R&R 文件定義 Problem、範圍、決策界線、routine、non-routine、SOP 引用與尚未訂定部分，不在各處重複維護人員名單。

### Routine 的觸發、時間與承接

Routine 是有可辨識觸發條件、可重複接續的工作，可以是固定週期、指定時間點，也可以由事件觸發。每項需能查到觸發條件、執行時間或期限、適用 SOP、執行者接受方式與完成證據。尚未訂定的時間與 SOP 明列，不自行推定每週、每月或即時回應。

週期安排要確認起算日、時間點與時區；事件安排要能辨識是哪次事件。期限需說明從事件發生、資料備齊或本人接受工作的哪個時間起算。未有約定期限時不得宣稱已逾期；期限未定也不代表事情已完成。

Leader 在現有職權內接續協作與決策。Contributors 由本人接受具體工作，或接受有明確期間、範圍及退出安排的重複工作；只加入 R&R 不等於接受其所有 routine。沒有已確認的執行者時記錄尚未承接；Leader 已接受的職責包含處理承接狀態與必要決策，不代表必須親自完成所有工作，不能自動指派其他 Contributors。此處不新增強制工作、時數或產量義務。

### Non-routine 的問題與決策

Non-routine 處理新問題、新提案或既有 SOP 無法判定的情況。對應 R&R 需說明要達成的結果、Leader 可自行決定的範圍、需共同決定的事項與對象，以及完成或停止條件。沒有 SOP 不代表不受制度與權限限制；流程有例外也不代表能降低原本門檻。

工作可在既有 PR、Plan 或工作紀錄接續，不要求每件事另建 Plan。需要反覆執行且處理方式已確定時，再依制度修改程序整理成 routine 與 SOP，不因做過一次就自動成為所有人的固定義務。

### 接續、交接與完成

1. 接手前核對原有紀錄、所依規格版本與實際狀態，避免同一事件重複操作。
2. 本次紀錄寫明工作範圍、本人接受、時間安排、成果與未完成項目；未接受、執行中與完成不能混為一談。
3. 跨 R&R 交接要說清楚交付什麼、交給誰、對方是否已確認接手。尚未接手或決定不一致時記錄阻擋；不能把送出訊息當成對方已接受。
4. 無人接受、資料不足、錯過約定時間、權限不足或 Leader 退出時，保留已完成結果，記錄原因與需要的接續決定。未有人接受時不能視為工作有執行者；不自動強迫他人補做或把未完成項目標為完成。
5. 完成證據依各 R&R 與 SOP 核對；操作失敗、待回覆及待接手只表示進度，不視為成果完成。公開紀錄不放帳戶憑證、私人聯絡資料或不願公開的內容。

Leader 的任免、跨 R&R 爭議與共同決定依本文件下列章節；不得由改文件、合併 PR 或修改 GitHub Team 取代有效任職或共同決定。R&R 的日常決策權不包含自行擴大職權。


## 審查權與通過條件

自介內容、真誠與意圖依本制度及憲法判斷。Onboard Leader 負責一般自介裁決；司法與覆核 Leader 處理 Onboard 本人的申請、原審查人的直接利益案件及審查異議。兩職須由不同人承接才能提供獨立覆核。AI 只協助核對、整理與準備 comments，不作最終裁決；其他 Leader 不因 Council 身分取得審查權。

由一位合格且非涉案人員完整核對並核准即可通過。申請者不能自審；有具體事實且尚未解決的有效異議時不得通過。單純不同意、背景評價或重複無新事實的反對，不自動形成阻擋；須依異議程序留下理由，不能以無回覆或一筆 Approve 假裝解決。沒有合格非涉案人員時維持待審，依一般補任接續，不臨時讓 Contributor 取得裁決權。

切換前依當時有效規則核准的資格保留；未完案件轉由現行合格人員接續，既有資料不重填。有具體錯誤才覆核，不以 Team 名稱反推舊資格。

案件分為收到、待補資料、完整排隊、已承接與決定完成，保留收到及資料完整時間。完整案件依備齊時間排隊，急迫例外須說明具體原因，不按政治立場選案。收到後七日內回報可否承接、待補內容或容量不足與排隊位置；承接後十四日內提供結果或具體進展，進展不是完成。完整案件排隊逾十四日可請求覆核是否選擇性拖延；沒有容量時公開等待並接續補任，不假稱已處理。期限是履行目標，逾期不自動免職，但反覆沒有實質進展可作監督或罷免的具體事實。申請者補件不設催辦期限。

核准針對實際看過的版本；新 commit 影響自介、照片、assignment 或審查結果時，須重新核對後確認結果。平台 Team 名稱不取代 R&R 的權限依據，也不自動授予 org Owner、額外 repo 管理權或其他組織決策權。

## 未通過與後續處理

| 結果 | 處理方式 |
|---|---|
| 需要補充或釐清 | 列出具體內容、依據與修改方式，保留 PR，等待本人補充；不設定定期催辦或逾期關閉。補充後重新審查。 |
| 明確違反組織原則 | 由有審查權限的人員引用具體內容與現行規定，說明未通過理由並關閉 PR，告知修正後如何重新申請。 |
| 尚未解決異議 | 暫不通過，由有審查權限的人員釐清並記錄處理結果；不把無回覆或已有 Approve 當成異議已解決。 |

補充資料與原則衝突分開判斷；缺欄位、斷連結或尚未說明的疑點，不直接當成不真誠。自介審查與 follow up 由處理該 PR 的有審查權限的人員接續；不由 Threads 招募客服追蹤或催辦。

## 通過與平台加入

自介審查通過後，依申請制度成為組織成員。PR 合併由具有該 repo 合併權限的人執行；org 邀請交由具有平台邀請權限的 org Owner 執行。有審查權限的人員負責交接通過紀錄、經核對的 GitHub username 與未完成狀態，不因缺少操作權限自行提高權限。

通過者只受邀成為 GitHub org **Member**，不加入 **Members team**，不因此取得 mono repo 的 Write；後續以 Fork／PR 協作。邀請接受後，才確認平台加入完成。已是 org Member 的通過者不用重複邀請；單純加入流程不回收既有 Team 與權限；職位終止或權限與有效職責不符時，仍須依「職位與權限交接」處理，不能以既有權限為由保留失效管理權。

具體核對表、操作順序、結果 comments 與失敗接續見[自介 PR 審查 SOP](<../03-SOP/[SOP]自介PR審查SOP.md>)；平台設定與驗證依 [GitHub org Setup](<../05-社群基建/[規格]GitHub-Org-Setup.md>)。




## Council 與 R&R

每位有效 R&R Leader 都是 Council，每位 Council 至少擔任一個 Leader，可兼任多個、數量不限。Council 不另設任期、定期重選或續任確認；同一人兼任不增加票。Contributors 至少選一項分工，選擇不等於已接受具體工作。

Leader 接受職責後，須維護責任範圍與必要紀錄、接續已接受工作及承接狀態、揭露無法履行與直接利益衝突、不逾權、退出時提供已有交接資料。不設固定工時、產量或例會，也不以目標期限自動認定失職。無法繼續者可辭任，書面公開其職位及生效時間；不必等到有人接手。失去最後一個 Leader 職位即退出 Council，仍為一般成員。

| 事項 | 決定者及成立條件 |
|---|---|
| 既定 R&R 範圍內日常工作 | 該 Leader 自主，具體工作由本人承接。 |
| 跨 R&R 邊界、共同操作規則、共同資源及對外合作 | 全體 Council 過半；不得強迫他人工作或出資。 |
| 新增、合併、停止 R&R，擴大職權 | 全體正式成員過半；提案列實際工作、權限、受影響人及接續。 |
| 一般 Leader 任命與補缺 | 全體正式成員過半；候選須有效正式成員且接受職責。 |
| 直接取消 Council／指定 Leader 替換 | 依「罷免與 Leader 替換」，不得以一般共同決定降低門檻。 |
| 修憲或實質減少成員監督 | 依「修憲及正式成員監督」，優先適用較高門檻。 |

單一正式成員即可提出以上事項，不需 Council 背書。普通制度變更屬共同操作規則；涉及職位、擴權、資格或監督時依相應規則，不能只改 SOP 避開門檻。合併或停止 R&R 涉及現任職位時，明列各職位終止、保留或接續；需新任命的部分須一併達成，不得借改名取得新權。

## 首屆任命與生效

首次建立的採納依據、一次性任命條件及生效紀錄，集中於 [Kickoff 的首次建立與首屆任命](../../plans/001-Kickoff/plan.md#首次建立與首屆任命)。本制度承接該次有效成立的正式成員及 Leader 資格；後續任命、補缺與撤換適用本制度的一般程序，不重新啟用首次任命權。

候選名單、歷史會議分工與平台 Team 均不是完成任命的證據。首屆名單尚未生效時，不得假稱已有有效 Council 投票；公開交流與自願工作可繼續，但不得冒用空缺職位作正式裁決。

## 提案、紀錄與投票程序

每案在 repo 公開一份案件紀錄（Issue 及必要 PR），Discord 發送通知並連回原案；沒有重複投票來源。提案人可自行發布，不依程序 Leader 私下收件或簽名放行。紀錄包含要解決的事、決定內容、版本、相關職位、人選接受、所需門檻、成員與 Council 資格證據、討論及投票起訖、票數、結果及執行狀態。

| 案件 | 討論期 | 投票期 |
|---|---|---|
| 一般治理、任命與罷免 | 七個完整日 | 七個完整日 |
| 修憲、實質減少成員監督 | 十四個完整日 | 十四個完整日 |

時間以 Asia/Taipei 的完整日期時刻記錄；一天為連續二十四小時。完整提案公開且通知連結發出時開始討論；互斥後案排隊，輪到且前提仍成立才開始自己的完整期間。期間內可討論、校對資格與修訂；實質修改須重新開始討論，開票後實質改版原案結束未通過，新版重新排隊；錯字修正留痕且不改實質。投票起點固定版本、名冊、門檻與截止，截止才判定，不提前通過。

票以本人可核對帳號在原案留下的明確同意、反對或棄權為準；截止前最後一份有效意思取代先前票，保留更正證據。無法核對身分、非該案資格人或逾時票不計入，列理由；單一自然人多帳號不增加票。公開記名會有社交壓力，仍不得因不同意而報復或取消無關資格。

## 投票資格與共同計票

名冊依有效審查、首次任命、任職、退出及恢復證據形成，不只看 main 表格；已核准未合併者與已有效恢復未登錄者都須納入。Onboard 提供資料，任何正式成員可整理核對，開票不以特定 Leader 簽名為條件。

Council 與正式成員各按全體不同的人為分母。每人一票，兼任不加票，未投、棄權及利益迴避不縮分母。同一 Council 的票在兩個集合分別計，不把兩邊票數相加。過半所需同意票為 floor(n/2)+1，三分之二為 ceil(2n/3)；n 為該路徑固定全體人數，零人路徑永不成立。人事當事人保留一票與陳述權，但不得覆核自己的程序爭議。

開票後正常入退會或職位變更不回算本案；原資格誤列或偽造不受固定保護。足以影響門檻的具體資格爭議須先由非涉案覆核者釐清，未釐清不開票；無具體理由反對不阻擋。開票後發現足以改結果的錯誤，停止依爭議結果新增不可逆操作，覆核更正後以正確名冊重開完整投票期；無關錯字留痕，不重投。

結果在截止時依固定規則及有效票成立，不靠計票者簽名授權。任何正式成員可公開重算；執行者操作前核對，不必另找固定雙簽。無人可執行時公開受阻，不能把已成立結果說成失效，也不能把未操作說成完成。已不可逆的錯誤行為逐項處理影響，不宣稱一切自動回復。

## 罷免與 Leader 替換

失職或失去信任均可由單一正式成員提案；列具體對象、理由及要變更的職位，不需連署、先私下協調或先給改善機會。指控須讓當事人知道具體內容並得以說明；投票依人事判斷，不以申請者能取得全部內部證據作提案前提。

| 層級 | 生效條件與結果 |
|---|---|
| 直接取消 Council，退回一般成員 | 全體 Council 過半或全體正式成員過半。全部 Leader 職位同時終止，保留一般成員，明列空缺及接續。 |
| 替換指定 Leader，接任者在開票固定 Council 名冊且生效時仍有效任職 | 全體 Council 過半或全體正式成員過半；同案指定已接受的接任者。原任者剩餘有效 Leader 不受影響。 |
| 替換指定 Leader，接任者不在開票固定 Council 名冊 | 須全體正式成員過半，整案同時生效；僅 Council 過半不產生部分撤職。接任者取得 Leader 時成為 Council。 |

接任者生效時須仍為有效正式成員並接受該職位。原案若同時安排原任者轉往新設或空缺職位，轉任須滿足一般任命條件；必要部分未一起成立，整案不生效。投票後不得換人。欲單獨撤 Council 而不等待接任者，可另提直接撤任案，不能把未通過替換當成直接撤任。

生效結果互不相容的案件按完整公開時間依序處理，包含同職位替換、直接撤 Council 的全部關聯職位及跨職轉任。前案結束後檢查後案前提；原對象／資格已變而不成立者結案，可按新現況重提，不把對舊人的票用於新人。後案不能重開前案，也不以多案票數互相加總。順位提供先處理優勢，仍須滿足相同完整期間與門檻。

## 修憲及正式成員監督

任何正式成員可提出修憲，決定權與門檻依[憲法第 12 條（修憲與成員監督）](憲法.md#第-12-條修憲與成員監督)，討論與投票依本制度的案件程序。

修憲提案使用專門修憲文書，記錄現行原文、修訂文字、修改理由及採納依據；可作為既有 Plan 的獨立附件，不要求每次另開 Plan。非修憲提案不能順便修改憲法。交付或推送前完成符合憲法的檢查，未通過或尚未採納的文字不得當成現行規定。這些是文件與工作安排，調整方式不改變憲法本身的修憲門檻。

實質減少正式成員監督的變更，不論寫在憲法、制度、SOP 或資格規則，都須全體正式成員至少三分之二。包括提案／罷免權、門檻、投票資格，以及新人進 Council 須正式成員同意的限制；不得用代理、暫任、改名或平台加入取得同等票權。按既定規則處理普通個案不逐案升級，執行者也不能自行擴大條件。

有人提出具體減權理由時，覆核 Leader 說明分類；涉及其直接利益或具體減權疑義未能排除，提案走正式成員三分之二，不由受益 Council 自證可以繞過。無新事實的重複異議可引用已有理由結案。

修訂依提案指定且不早於通過的時間生效；未指定則通過時生效。不追溯改算已開票案件，真正原始錯誤仍依覆核更正。首次建立的採納紀錄不作為日後規避修憲的依據。

## 異議、利益衝突與錯誤處理

司法與覆核 Leader 處理入會、名冊、資格及程序異議，核對是否符合已定規則，不取代有效的人事選擇。Onboard Leader 僅在覆核 Leader 無法接手且不是自己的決定或直接利益案件時備援；兩職由同一人承擔不能構成獨立覆核。兩者均涉案或空缺時，依一般任命補上合格者並公開受阻，不臨時授予第三人裁決權。

任何申請者或正式成員可提出具體疑點及已有資料，不要求先拿到所有證據。受理、排隊、容量與進度依審查共通安排；結論列適用規則、核對事實、理由、處置與接續。新事實可重開，重複無新內容引用原答覆。覆核者也受既定罷免，不享永久豁免。

直接私人利益須揭露，不參與該案的實質核准、裁決、覆核或執行（包含驗收）；可提供事實及答辯。共同受一般規則影響不等於人人須迴避。人事案本人投票與陳述依本制度保留，但不得覆核自己。

有具體偽造、越權或資格錯誤疑點時，合格覆核者可具理由暫停爭議部分執行，最長七日，不停無關工作。未證成不得以同一疑點無限延長；證實無效的決定不因期滿變有效。錯誤處理涵蓋原資格、職位、受影響投票及損害，必要時更正與重投，不只處理未來恢復。無法完成覆核時明示受阻，不自行宣稱無異議。

案件公開程序、必要理由與結果；私人聯絡資料、憑證及未查明敏感證據只供有權且非涉案者受控查核。不能以透明為由公開秘密，也不能以保密為由不給必要理由或拒絕合格查核。

## 組織資源與私人利益

涉及組織名義、資金、活動機會、資料、署名或資產的共同決定，提案列用途、具體受益者及關係、金額或非金錢利益、交付內容與可比較替代。相同目的的支出合併揭露，不拆案規避檢視。直接受益者不核准或驗收自己的案件；仍依全體 Council 分母，合格非涉案同意票須過半，不足則不做該交易並另找方案。

執行限已核准範圍，支出須有明列來源及必要持有人同意，不創個人墊款義務；公開實際交付與支出證據，敏感資料受控。已核准用途內例行操作不逐筆再投票。不得以發言、名單存取、署名或職位交換支持；非營利、不得推銷及收費置入等憲法限制不因多數同意而失效。

## 職位與權限交接

Leader layer 與 permission layer 對應，但 Council 身分不授予全部平台權限。普通成員資格、Council、個別 Leader 及平台角色分別核對；平台名稱與實際能力須由有效職責及權限清單支持。

| 責任範圍 | 決策與操作權配置 | 接續要求 |
|---|---|---|
| Onboard | 自介裁決、普通成員名冊處理、合格時有限覆核備援 | 不因此取得 org Owner 或所有 repo 合併權；平台邀請交具相應操作權者。 |
| 司法與覆核 | 合格非涉案的資格及程序裁決、錯誤修正 | 核對證據不等於可任意加人或自行改門檻。 |
| Repository | GitHub／Discord 維護、依有效決定合併、邀請及角色權限操作 | 所需平台權限逐項核實；不能因操作能力自行決定正式資格或任命。 |
| Domain-Name | 已確認網域之設定、續約與移轉 | 所有權及恢復能力須有真實依據，不能把個人資產假稱組織已控制。 |
| 其他 R&R | 只持自身有效職責需要的權限 | 特殊接續職責須在該 Role 明列，不因 Council 身分取得。 |

每個關鍵平台須有兩位不同有效 Leader 各用本人帳號，具必要接續或恢復能力。同兩人可跨平台，不按平台增設席位。第二人的 Role 必須明列接續責任、使用情境與權限，備援不得任意決定原業務。新增備援職權依擴權程序，不能只改權限表。單一 Owner 等限制須核實恢復路徑；做不到就記錄接續能力不足，不假裝已完成。任一人離任而剩一人時同樣標示不足。

職位終止時立即失去其決策權；具有效操作職責者二十四小時內啟動撤權／移交，以七十二小時完成為目標。原任拒交不延任，由已有接續能力者或平台正式恢復途徑處理。只撤失效職責的權限，保留其他有效職位與一般權益。無可行恢復途徑時公開受阻及工作影響，不保證可收回私人資產。

交接包括有效決定、工作與資料清單、資產保管位置、未完承諾及期限、接手者接受與實際權限驗證；公開紀錄不放憑證。名單更換、本人接受、平台操作與驗證分別記錄，不能把其中一項當全部完成。

## 緊急處置

現有具相應權限的 Leader 得為正在發生的入侵、資料刪除或其他具體傷害，作必要最小暫時處置，例如撤銷被盜登入、暫停受害帳號操作、保存證據。不得藉此永久任免、取消成員資格或授予新永久權限。

處置後二十四小時內提供不含秘密的紀錄，七十二小時內由非本人且無直接利益的覆核 Leader 或合格 Onboard 備援檢查必要性與恢復，以此為目標而非無人也能完成的保證。無合格者則公開受阻、停止擴大措施並依一般程序補任。沒有安全恢復條件不機械重開被盜帳號；持續限制須有理由、可行替代存取及下次檢查時間，不能轉成無限期懲罰。

## 長期不參與與成員資格處理

一般正式成員每季統一清查一次，使用相同截止時間及條件，不針對某次罷免或特定立場選人。週期自規則正式通知成員之日起每三個月，首次一百八十日未滿不得產生清查終止；Onboard 公開起算與本次截止。無可確認參與或回覆一百八十日才進通知，交流、學習、協作或本人回覆均可確認，不要求工時、成果或公開私下內容。

1. 以成員約定個別管道通知，給三十日回覆，第十四日提醒；表示願意保留即保留，不要求解釋私人原因。
2. 送達失敗時，在不同日聯繫兩次並留下紀錄，再於預先約定公告處給額外三十日。通知管道與公告處須先由本人可得知的加入／規則通知記錄確立，不能臨時選不知情位置。
3. 期滿無回覆，由兩位無直接利益正式成員核對通知、期間及回覆；至少一位不是提出該變更者。Onboard 依明定條件作決定；無獨立核對者不移除，有具體異議交覆核，不作選擇性清查。
4. 決定公布時終止普通成員資格，保留公開交流與過往署名；只處理依此資格取得的權益，不以失聯等同不當行為。已開票案件依固定名冊，不回算。

仍任 Leader 者不適用上述行政資格終止，未履行職責由辭任／罷免處理；離任後的無參與期間自離任時重新起算。不得先清查取消資格來繞過撤 Council 門檻。正常低頻參與、單次不投票、沒公開發言或未接工作均不能直接除名。

首次採納依據保留於 [Kickoff 的首次建立與首屆任命](../../plans/001-Kickoff/plan.md#首次建立與首屆任命)，實際通知成員後才起算，不回溯清人；後續此資格規則變更須全體正式成員三分之二。若既有分母已難達門檻，不得先移除成員再採納變更。全體都回覆保留卻不投票時仍可能無法決定，不以清查偷降全體分母。

自願退出可由本人公開明確表示並指定不早於提交的生效時間；仍任 Leader 者若退出正式成員，須同時明列全部職位辭任，由本人意願一併生效，不冒充行政撤任。

### 恢復與原錯誤更正

曾有效且因自願或本清查退出者，以原已驗證帳號公開完整聲明願遵守制度、恢復參與並選至少一項有效 Contributors，即依規則生效；原分工停止則改選。Onboard 更新表格是登錄，不以其晚回覆延後資格；不重寫自介，也不自動拿回 Leader。恢復後才開票案件納入，已開票案件不回算。

原帳號失效、本人對應不明或原退出原因不屬上述兩類時，按證據查核，保留申請時間，不套自動恢復。原退出若有錯誤，交覆核處理原資格、原職位及受影響投票，不僅恢復未來，也不自行奪回已有有效接任者職位。

本制度不授予永久懲罰性取消一般成員資格的權力。原資格偽造或重複身分依原有加入條件查核，不能自行增加除名條件。未來如需設永久除名，須先由全體正式成員三分之二採納具體違規條件、通知答辯、非涉案裁決、覆核及恢復安排；普通 Council 共同決定不能自行創設。

## 制度修改與執行調整

憲法完整規定組織目的、基本權利義務、權力來源及界線、監督與修憲；本制度補充共同運作程序，Role 定義職責與所需權限，SOP 定義操作。下位規則不得改變上位規則；判斷變更所需程序依實際影響，不依文件名稱。

| 變更內容 | 決定方式與邊界 |
|---|---|
| 既定職責與共同程序內的工具、表單呈現、留言或操作步驟 | 由負責 Leader 自主決定；不得改共同資格、義務、權限、期限或其他人的責任。 |
| 共同通知、案件期間及其他共同程序 | 全體 Council 過半；須維持憲法保障的知情、參與及異議機會。涉及實質減少監督時改用正式成員三分之二。 |
| 分工增減、擴權及任命 | 依「Council 與 R&R」及「罷免與 Leader 替換」；不因寫在 Role 或 SOP 就變成個別 Leader 自主事項。 |
| 變更成員資格或實質削減監督 | 依「長期不參與與成員資格處理」及「修憲及正式成員監督」的較高門檻；不得先改名冊再表決。 |
| 改變憲法核心、權力來源或憲法所定門檻 | 正式提出修憲；即使在其他文件寫出相反規定，也不產生改憲效果。 |

僅修改操作方法而不改變共同規則，不另作共同表決。例如調整自介審查 comment 的排版可由該職責 Leader 決定；縮短共同審查期限則屬制度變更。新增 R&R 依成員過半決定，不因增加分工就必須修憲。改變修憲門檻則必須修憲，且依是否實質減少監督判斷適用路徑。

制度調整記錄於對應 Plan 並檢查是否符合憲法；本次啟動範圍由 Kickoff 統籌，不按每次改字另開計畫。規則生效仍須有有效決定，不能以合併文件取代。修改操作方法、文件位置或檢查工具，不免除任何人的憲法遵循義務。
