# 成員識別與資料

## 問題

稱呼可以重複或修改，自介路徑也可能隨帳號改變。若只靠名字或檔名辨認，個人成員檔案、R&R assignment、資格紀錄與歷史貢獻就可能把同一人當成不同人，或把不同人當成同一人。同時提交的申請若自行取得下一個編號，也會撞號。識別規則須保持可追溯，又不能把編號配置當成取得資格的另一道裁決。

## Specs

### 身分與唯一性

| 資料 | 定義及維護 |
|---|---|
| Member ID | 組織內唯一的六位數正整數字串，保留前導零；固定、不回收、不重新分配 |
| GitHub 帳號 | 本人目前用於 PR 與平台操作的帳號；以不分大小寫比對唯一性，檔名使用小寫 |
| 本人稱呼 | 給人閱讀，可以重名或修改，不作唯一識別 |
| 個人成員檔案 | 每人一份；維護編號、目前帳號與自介 |
| R&R assignment | 分工的唯一維護來源，以 Member ID 核對人，顯示稱呼並連到自介 |

一個自然人只有一個 Member ID，同一個目前 GitHub 帳號不得對應不同人的自介，包含申請中與已退出資料。無法核對是否為同一人時保留疑義，不自行合併、另發身分或要求公開私人證件。歷史帳號只作來源紀錄，不視為本人仍控制該帳號的證明；帳號對應改變須保留可核對依據。

編號不是資格、資歷、職位或權限。資格仍依[憲政制度](<[機制] 憲政制度.md#申請與成員資格>)成立；尚未編號或資料尚未合併不能取消既有有效資格。資料疑義依既有異議與覆核程序處理。

### 自介檔名與欄位

正式檔名為 `members/<六位數編號>-<小寫GitHub帳號>.md`。自介正文記錄 `Member ID：<六位數編號>`、`GitHub：<目前帳號>` 與本人稱呼，編號及帳號須和檔名一致。

初次申請尚未配置編號時使用 `members/pending-<小寫GitHub帳號>.md`，正文寫 `Member ID：待配置`。pending 是暫存檔名前綴，不是 Member ID。申請以自介 PR 保存本人帳號及審查紀錄；不以猜測數字填入編號欄。

已有身分的人更新或恢復時沿用原編號與自介，不另建 pending 自介。照片沿用 `members/assets/` 的實際引用，不以照片檔名辨認身分。

### 資格與變更紀錄

自介只維護個人資料，不填資格狀態、狀態生效時間或狀態依據。一般入會以自介 PR 已依制度審查通過且合併為準，生效時間直接讀取 GitHub 的 PR 合併時間，不抄進檔案。僅 Approve、一般資料更新 PR 合併或未經有效審查的合併，都不能自行取得資格。

入會審查留在自介 PR 的 review；退出、恢復與更正依憲政制度，把本人聲明及有效決定留在相關 PR／Issue 或引用的有效紀錄。Git diff 與 PR 歷史保存變更，不另手寫資格流水帳。退出、恢復及首屆任命不是新的普通入會，不因取消欄位就改成等待平台合併才生效；依各自規則核對。

不另維護手動成員總表；入口在 [members README](../../members/README.md)。查資格時由自介申請 PR 與後續有效紀錄核對，不能只憑自介存在或某次資料編輯判定。退出仍保留原檔、編號與歷史署名。既有有效資格及已開始投票案件依制度的過渡與不溯及規則處理。

有效 R&R 只在 assignment 維護，不在自介另抄分工名單。Contributions 是能力與意願，不等於任職；可連到相關 R&R，但不能從自介推定有效分工。

### 編號配置與合併

有合併權限的人負責配置，不能因此裁決入會資格。一般申請依[自介 PR 審查 SOP](<../03-SOP/[SOP]自介PR審查SOP.md>)先取得有效通過結果，再完成以下資料操作；其他已有有效資格者以相應依據辦理。

配置前核對最新 main、所有個人成員檔案（包含已退出）、Git 歷史與相關申請。已存在同一人時沿用原編號；不存在時，取歷來已配置最大編號加一，補成六位數，沒有任何已配置紀錄時由一開始。退出或刪除檔案不釋放編號，須核對 Git 歷史與相關 PR 紀錄。六位數用盡時先修訂格式，不截斷或重用。

編號以完成合併的配置紀錄為準，PR 中的候選編號不構成預留。合併人員依序處理配置，不同時合併競爭同一編號的 PR；每次合併前重新讀取 main，若有其他配置先合併，須重新計算並核對最終版本。不能只靠 Git 沒有文字衝突推定沒有編號衝突。

同一個 PR 更新檔名、正文及全部受影響的 assignment 連結，再確認原核准適用於最終版本。配置後一旦發現重複，不直接重新發號掩蓋紀錄；先停止受影響的後續操作，依原合併紀錄確認對應並修正，資格爭議交既有覆核程序。

### 變更、退出與恢復

- 改本人稱呼只更新顯示文字，不改編號或檔名。
- 改 GitHub 帳號時，由 Onboard 依既有資料與可核對的本人確認核對對應；有疑義交非涉案者覆核，不以新帳號單方面聲稱為據。保留編號，在同一 PR 更新正文、檔名及所有有效引用，保存前後帳號與核對依據。歷史原話與已完成紀錄不重寫。
- 退出後保留原編號、自介及退出依據；恢復沿用原編號，不自動恢復 Leader。沒有配置編號的未通過申請不占用編號，已有歷史編號不得回收。
- 編號資料整理不提高加入的能力、背景或文章品質門檻，也不改變資格生效時點、表決權及申訴保障。
