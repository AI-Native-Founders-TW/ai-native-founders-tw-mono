# Credits 文案

文案來源：[credits.zh-tw.yaml](<../../../modules/ai-native-founders-tw-web/src/content/copy/credits.zh-tw.yaml>)。本頁按敘述順序閱讀；共用頁首頁尾見 [landing-page 入口](<README.md#共用頁首與頁尾>)。

## 每個人做的事，都應該被看見。

這份名單不是手動維護的。程式貢獻來自 git 紀錄，組織文件的署名來自 mono 各文件的「資訊貢獻者」，設計、文案等 git 看不到的貢獻則寫在 credits.yml。

頁面導覽標示為「Credits · 工作人員名單」。統計資訊包含貢獻者人數、貢獻筆數與署名文件份數，並標示資料來源及產生時間；數字依實際資料顯示，不在文案中固定。

## 網站製作

Owner、Collab 與各角色，以及這個網站 repo 的 commit 作者。

網站角色包含「Owner」「Collab」「Logo」「文案初稿（依會議逐字稿起草）」「文案協作」「AI 協作工具」「AI 工具」。程式貢獻的數量使用「commit」或「commits」標示。

## 組織文件資訊貢獻者

mono 各文件末尾列名的資訊、經歷與見解貢獻者（憲法第 10 條）。

此區提供「依文件」「依人」兩種查看方式；文件入口標示為「在 GitHub 看文件」，數量單位為「份文件」。

## 社群

mono 的 commit 作者，以及已合併的自介。

自介資料提供「自介」「提交自介」「看自介」入口，另呈現「會議分工」與「mono commit 作者」。實際人名與名單依資料來源顯示。

## 怎麼把自己加進來

### 寫程式

commit 進本 repo 或 mono，下次建置自動出現。

### 設計、文案、討論

在 PR 裡順手把自己加進 src/content/credits.yml 的 website.roles。

### 頭像

在 credits.yml 填上你的 GitHub 帳號，就會換成 GitHub 頭像。

### 名字對不上

同一個人有不同稱呼時，在 credits.yml 的 aliases 合併。

行動入口：「編輯 credits.yml」。

## 資料讀取與空白狀態文字

讀不到 mono 時顯示：「目前讀不到 mono，以下是暫時的資料。」沒有已合併自介時顯示：「還沒有已合併的自介。你可以是第一位。」這些是條件成立時的介面文字，不代表目前實際資料一定處於該狀態。

## 來源與制度差異

「憲法第 10 條」是網站來源保留的舊署名條號，不作現行條文引用；現行知識內容署名依[憲法第 2 條（公益與非商業性）](<../../01-制度/憲法.md#第-2-條公益與非商業性>)。會議 credit 目前保留於來源會議記錄，不另建資訊貢獻者彙整檔。

本文保留網站既有的名單來源與自動產生說明，不藉文案整理宣稱資料邏輯已改、每個人已列名或網站已同步。網站與制度的差異仍由 [Kickoff](<../../../plans/001-Kickoff/plan.md#2026-10-29-文案萃取修正>)追蹤。
