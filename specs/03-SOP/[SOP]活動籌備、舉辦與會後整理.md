# 活動籌備、舉辦與會後整理

適用於線上或實體活動。每場由明確接受工作的召集人接續籌備、公告與收尾；協作者由本人接受具體工作，小型活動可由同一人承接多項。需要協助時可找[活動籌辦與協助](<../02-R&R/[Role]活動籌辦與協助.md>)，確認其可承接的項目；每場召集人仍負責該場籌備與收尾。自行辦活動不需先經該 Role 核准。

## 資訊放在哪裡

| 位置 | 用途 |
|---|---|
| mono 的 GitHub Issue | 想法、籌備討論、工作認領及決定依據。簡單且已確定的活動不必補開 Issue 或 Plan。 |
| Discord `events` forum | 參與者的主要入口；同一活動維持同一篇，放公告、問答、異動及會後摘要。 |
| Discord 原生 Events | 活動排程與開始通知，連回 forum；forum 也附排程連結。Interested 不取代另行要求的報名。 |
| mono | 保存可長期使用的筆記、教材與活動紀錄，由 forum 連回；不公開報名者個資或憑證。 |

## 怎麼做

1. **提出想法並找到願意承接的人。** 說明活動目的、適合對象、形式與需要的協助；尚未確定時先走[提議與號召討論](<[SOP]提出提議或活動與號召討論.md>)。確認本次召集人及必要協作者已接受工作，沒有回覆不等於接受。
2. **確認活動辦得成。** 核對時間與時區、場地或線上工具、講者／主持接受、名額與參與方式。涉及共同資源、跨 R&R 決定或對外合作，先依[共同事項與表決 SOP](<憲政/[SOP]提出共同事項與參與表決SOP.md>)取得有效決定；普通活動不因此一律送 Council。未確認的日期、費用或人選標為暫定，不先替他人承諾。
3. **在 `events` forum 公告。** 已有同一活動貼文就更新原篇；使用下方公告內容，讓參與者找得到完整資訊。排程確定後建立自己的原生 Events，與 forum 互相連結。一般加入者可建立自己的活動；不因召集活動取得管理他人活動或發布 announcements 的權限。
4. **活動前確認與提醒。** 測試參與者可使用的連結、場地設備及音訊，確認講者與協作者仍可出席，準備簡短流程與異常聯絡方式。按活動需要安排提醒並留下時間；不規定所有活動都必須提前相同天數，也不依賴大量提及。報名只蒐集必要資料，不把名單放在公開 Issue。
5. **舉辦活動。** 開場說明目的、流程、交流方式及拍攝／錄影安排，提供不被拍攝或公開的選擇。按本人接受的分工接續主持、協作與紀錄；未取得同意的影像、私人談話及個資不公開。若有原生 Events，確認其開始狀態，不把實際開場當成排程已自動啟動或通知已送達。
6. **有變動就同步通知。** 改期、取消、講者缺席或設備故障時，明確說明繼續、改形式、延期或取消，更新 forum 原篇、原生排程及既有報名通知管道。有已收款或已作外部承諾時，由有權負責者確認處理方式與接續；不以刪掉活動當成退款或承諾已處理。
7. **活動後在同篇 forum 發布摘要。** 以隔日先發短摘要、一週內補齊整理內容為目標；小活動可一次完成。使用下方會後內容，沒有錄影也能發摘要。若資料仍待整理，標明已接受整理的人與預計補充時間；未有人接受就明列未承接，不虛構完成。
8. **保存知識並確認收尾。** 將值得長期使用且可公開的內容整理進 mono，保留來源與資訊貢獻者署名，再連回 forum。核對未完承諾、必要結算與後續工作，記一項下次值得保留的做法及一項可改進之處。準時結束活動不等於收尾完成；未完事項要有接續紀錄。

## 活動前公告要有什麼

- 活動名稱、目的與適合對象。
- 日期、時區、起訖時間，以及地點或會議連結。
- 簡短流程、講者或主持；尚未確認者標為暫定。
- 如何參與、是否需要另行報名、名額及已確認的費用資訊（若有）。
- 召集人與聯絡方式、拍攝／錄影及公開安排。
- 原生 Events 連結；有籌備 Issue 時附上連結。

費用、合作與活動內容仍受[憲法](<../01-制度/憲法.md>)及[組織資源規則](<../01-制度/[機制] 憲政制度.md#組織資源與私人利益>)約束；公告欄位不代表新增收費、推銷或置入權限。

## 活動後至少留下什麼

- **實際結果：**活動是否如期舉行、做了什麼，以及重要收穫；取消或未舉行就如實說明。
- **內容入口：**可公開的筆記、教材或錄影連結；尚未整理就說明狀態。
- **致謝與署名：**講者、資訊貢獻者與協作者。
- **後續事項：**接下來要做什麼、誰已接受、預計何時接續；沒有下一步也可直接寫明。

## 如何確認完成與例外

活動前找得到怎麼參加，活動後在同篇 forum 找得到結果與知識入口，未完事項有已接受的接續者或明確標示未承接。若仍有未完成的結算、承諾或整理工作，維持未完成狀態，不能只因活動結束或 Issue 關閉就標成全部完成。

召集人無法繼續時，交代現況並找願意接受的接續者；無人承接就明確告知延期、取消或受阻，不把工作轉嫁給未接受的人。會後時間為履行目標，無法如期時更新原因與預計時間，不自動認定失職或改變成員資格。

無法發文、修改排程或取回資料時，保留待辦並向具相應平台職責者求助，不自行提升權限。正在發生的入侵或資料刪除等傷害依[緊急處置](<../01-制度/[機制] 憲政制度.md#緊急處置>)先處理，再接續通知與紀錄。

頻道與平台權限依 [Discord 社群 Setup](<../05-社群基建/[規格]Discord-社群-Setup.md#活動建立與參與>)，工作承接依[共同制度](<../01-制度/[機制] 憲政制度.md#routine-與-non-routine-responsibilities>)，長期知識整理依[志工協作與開源知識](<[SOP]志工協作與開源知識.md#開源知識如何被使用>)。
