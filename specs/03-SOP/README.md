# SOP

## 主要放什麼資料

本 package 放憲政權利行使、志工協作、開源知識整理及 Threads 引流招募客服的運作方式。SOP 說明執行者要做的步驟、要確認的結果、例外處理與交接；要傳送的公版訊息直接放在對應步驟的 payload。

## 文件入口

| 文件 | 主要資料 |
|---|---|
| [活動籌備、舉辦與會後整理](<[SOP]活動籌備、舉辦與會後整理.md>) | 每場召集人接續籌備、events 公告、舉辦、異動與會後知識整理。 |
| [提出提議或活動與號召討論](<[SOP]提出提議或活動與號召討論.md>) | 先在 mono 開 Issue 分享想法、找人討論，再依需要接續協作、PR、Plan 或正式決策。 |
| [憲政 SOP](<憲政/README.md>) | 按成員意圖找到共同表決、分工、任命、罷免、交接、覆核、成員資格及修憲的八份操作指引。 |
| [自介 PR 審查 SOP](<[SOP]自介PR審查SOP.md>) | 逐項審查標準、結果 comments 與 GitHub 加入接續；由 Onboard Leader 依共同制度裁決，非涉案覆核人處理異議。 |
| [志工協作與開源知識](<[SOP]志工協作與開源知識.md>) | 志工時間、申請成本、找人協作與知識取用的 Problem，以及已確認運作和未決構想。 |
| [Threads 引流招募客服 SOP](<[SOP]Threads引流招募客服SOP.md>) | 留言與私訊客服、邀請公版、發送前核對、送出後驗證與邀請日誌記錄。 |

工作流文件的存在不表示平台設定或外部操作已完成；尚未決定的安排依各檔與其 Plan 說明，不因文件已存在而當成平台已完成設定。

Discord 與 GitHub 的設定、權限及行為規格見[社群基建](<../05-社群基建/README.md>)；本目錄維護執行步驟，操作時引用對應平台規格。
