# Threads 引流招募客服 SOP

# Problem

加入詢問散在留言、續串與私訊，同一人可能出現在多處，容易漏回或重複邀請。這份 SOP 說明如何接續處理，減少[加入申請的處理成本](./[機制]志工協作與開源知識.md#我們能不能減少我們的營運成本)。

# Specs

## 開始前

確認本輪由誰處理、誰拍板，以及目前可用的 Discord 邀請與申請入口。先看上次紀錄，避免多人同時處理同一人。只整理或試跑時，不接受陌生訊息、不發訊息或邀請。

## SOP

1. **看完整對話。** 查看新留言、續串、必要圖片，以及收件匣、陌生訊息和隱藏訊息，了解對方在問什麼。

2. **確認有沒有處理過。** 以完整 Threads 帳號核對紀錄和 Johnny 的最新回覆，合併同一人的不同來源。曾答應邀請不等於已發送；送出結果不明時，先查看實際對話，確認前不重送。

3. **回答問題，確認加入意願。** 依現行制度回答，優先接續既有私訊。只表達支持或被別人標記，不代表同意加入；先問本人。遇到尚未決定的規定，記下問題，交給拍板的人確認。

4. **提供邀請與加入說明。** 本人願意參與後，再看一次最新對話，核對收件人、內容、既有邀請及有效入口，確認沒有其他人已處理。記下準備發送的動作，再提供 Discord 邀請與申請說明。同名或同頭像不能當作跨平台身分證據，須由本人確認。沒有有效入口時先保留待確認；不要自行建群、核准申請或授予權限。

5. **確認實際結果。** 發送後查看實際內容，確認成功才記完成。邀請送出、進入 Discord、提交申請與取得成員身分分開確認，資格依申請制度判定。

6. **更新紀錄，交接未完成事項。** 記下帳號、問題、來源連結、處理時間、已做的事、結果證據與下一步。尚未讀到的範圍或無法確認的結果也要記錄，交接給本輪拍板的人與後續負責人。

## 注意事項

- 同一邀請不要重複發送；對方有新問題仍可回覆。本人拒絕或要求停止聯絡時，停止主動邀請。
- 分批處理，避免短時間大量貼相同內容。遇到頻率限制、登入或驗證阻擋，停止受影響的發送，記下停止位置；恢復前先確認先前動作的結果，不連按或換帳號繞過。
- 私人對話、聯絡資料及逐人處理紀錄存放在有權限的位置，不貼進公開 repo；邀請連結也不要未經確認就公開。
