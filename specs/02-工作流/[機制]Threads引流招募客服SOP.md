# Threads 引流招募客服 SOP

# Problem

想加入的人會在不同 Threads 貼文留言、被別人標記，或直接私訊。同一人也可能先留言再私訊；若沒有接續讀取與處理紀錄，就容易漏回、重複邀請，或把已發邀請當成已加入。

本流程承接[加入申請的處理成本](./[機制]志工協作與開源知識.md#我們能不能減少我們的營運成本)，將引流、招募與客服接到目前的加入方式。目的在讓有意願的人知道如何參與，並持續處理其問題，不推銷特定公司的產品或服務。

# Specs

## 適用範圍與處理結果

本流程由一位本輪執行者接續操作 Threads 與 Discord，並依[憲法第 16 條（每事有人拍板）](../01-制度/constitution.md#第-16-條分工與決策)確認至少一位拍板的人。使用 AI 時，由同一個 agent 使用 computer use over browser，不同 agent 不同時回覆同一帳號或發送邀請；AI 執行者不取代拍板的人。

目前對外招募與加入詢問的來源包括：

| 來源 | 處理範圍 |
|---|---|
| [不限背景的參與邀請](https://www.threads.com/@johnny850807/post/DeyYRITE-3t) | 本文、作者續串、留言及留言回覆 |
| [Startup School 與創業交流](https://www.threads.com/@johnny850807/post/Dex7DjDE_VQ) | 想加入社群、交換知識與參與交流的留言及回覆 |
| [出海創業交流與 Coffee Chat](https://www.threads.com/@johnny850807/post/Devi1LHEw4a) | 留言、被標記者及後續交流詢問 |
| Threads 私訊 | 與上述招募及社群參與相關的收件匣、陌生訊息與隱藏訊息 |

現行規格已決定[改用 Discord](./[機制]志工協作與開源知識.md#社群搬到-Discord)，LINE 群不再使用；舊貼文、舊私訊仍提到 LINE 時，接續說明目前的 Discord 安排，不再發 LINE 群邀請。這項決定不表示搬移與設定已完成。

處理紀錄分開辨識：已回覆問題、邀請已送出、已進入 Discord、已提交申請、已取得成員身分。前三項不能推定後兩項；加入組織依[申請制度](../01-制度/[機制]申請制度.md)。

本 SOP 記錄目前流程；不表示 Discord 邀請方式、自介審查人或所有操作都已完成設定與實測。尚未確認之處列於 Note，不自行補成制度。

## SOP

### Phase 1 -- 確認本輪範圍與尚未處理的事項

1. READ 讀取本輪指示、目前加入與協作規格，以及前一輪紀錄，確認這輪是盤點、草稿試跑或實際客服與邀請；建立文件或試跑，不代表要向真實帳號發訊息。
2. READ 核對目前 Discord 目的地與加入說明；只有舊 LINE 資訊、過期邀請或來源不明的連結時，將該項保留待確認，不替換成猜測的目的地。
3. THINK 確認本輪至少一位拍板的人、已拍板的處理範圍與一位執行者，再核對是否有人正在處理同一批對話；拍板的人未定時，可整理資料，先不做依賴拍板的外部發送。使用本地紀錄工具時，先取得整輪排他鎖；鎖已存在便跳過，不刪除不屬於自己的鎖。
4. WRITE 記下本輪範圍、開始時間及上次尚未讀到的分支；本輪有關閉或中斷時，仍須保存紀錄並只釋放自己持有的鎖。

### Phase 2 -- 讀取留言、續串與私訊，合併同一帳號

1. READ 使用已登入的 Threads 帳號，逐篇讀本文、作者續串、留言與必要圖片；用最新排序補讀新增留言，並展開與加入詢問相關的回覆分支，不只讀搜尋摘要。
2. READ 分別查看收件匣、陌生訊息與隱藏訊息，開啟相關對話讀取完整上下文；列表預覽或未讀數不能當成全部訊息內容。
3. THINK 以去除前導 @ 並轉小寫的完整 Threads 帳號合併跨貼文及私訊來源，保留底線與點；不依顯示名稱合併，不將引用卡片中的帳號誤認為留言者。
4. READ 核對既有處理紀錄及 Johnny 已手動回覆的內容。曾說「週末邀請」不等於已發邀請；已恭喜 Startup School 錄取也不等於已回覆入群問題。
5. READ 遇到上一輪已開始但尚未確認的發送動作，先回讀對話與邀請現況；確認前不重送。
6. WRITE 保存問題原文、來源連結、觀察時間、本人參與意願與下一步。無法載出的分支記為未讀，後續補讀保留少量重疊，不因捲到底或看見回覆數就聲稱全部讀完。

### Phase 3 -- 回覆問題並說明目前加入方式

1. THINK 區分想加入、詢問規定、願意交流或貢獻、只表達支持、被第三人標記，以及明確拒絕。只表達支持或被標記，不等於本人已同意加入；先提出參與邀請並取得回應。
2. READ 依[申請制度](../01-制度/[機制]申請制度.md)及[第五章（開放）](../01-制度/constitution.md#第五章開放)回答資格問題，說明制度當時規定的申請方式、審查與成員身分取得條件；不自行增加制度以外的門檻。
3. WRITE 依對方實際問題及已確認規定形成回覆，沿用 Johnny 的用詞。舊文提到「直接私訊就能加入」時，依申請制度說明目前的加入與 Discord 安排，不將舊文的說法直接當成現行成員資格。
4. THINK 遇到尚未決定的群規、審查安排、交流場次或合作承諾，保存原問題與需要補充的事項，只暫停依賴該答案的部分；不自行指定審查人、通過條件、活動名額、募資結果或回覆期限。
5. THINK 核對同一人是否已有可接續的私訊；有則優先在原對話處理，不在公開留言及私訊各送一次相同邀請。私人聯絡資料、對話內容與邀請連結的公開範圍須分開核對，不因能讀到便公開貼出。
6. WRITE 送出前重新讀取目標對話，確認收件帳號、問題、完整內容及 Johnny 尚未手動處理，再先記下本次預計動作與開始時間，才實際發送。陌生訊息的接受與客服訊息的送出分開記錄；接受會讓對方知道已讀，試跑不按接受。
7. READ 送出後回讀實際內容、收件者與回覆位置，保留可核對連結與操作工具要求的證據。回讀證實才記成功；結果不明保留待確認，不因輸入框清空就重送或判成功。

### Phase 4 -- 接續 Discord 邀請與加入申請

1. READ 核對本人願意參與、最新對話、既有邀請及 Discord 現況。Threads 與 Discord 帳號的對應以本人提供或確認的證據建立，不以同名或同頭像猜測。
2. WRITE 使用已確認的目的地及邀請方式，向對方提供目前 Discord 交流入口和申請制度當時規定的加入說明；缺少有效邀請或申請提交位置時，先保留該項待確認，不自行建立另一個群或要求改交私人表單。
3. READ 回讀邀請是否送出，分開核對對方是否已進入 Discord；再依申請制度與實際申請、審查結果更新紀錄。沒有申請制度所定取得成員身分的證據時，不標成已成為成員，也不以發過邀請代替確認。
4. THINK 申請審查依申請制度及實際有權處理者接續；誰審、審查程序與 Discord 權限怎麼配合尚未決定時，保存申請位置與未完成部分，不由客服代為批准、合併或授予權限。
5. WRITE 已發邀請者有新問題時繼續客服，但不因新的留言或私訊來源又發同一邀請；本人拒絕或要求停止聯絡時，記錄並停止該人的主動邀請。

### Phase 5 -- 處理發送限制與中斷

1. THINK 依每個人的上下文逐案回覆、分批處理，不短時間連續大量貼相同內容；不把任意每分鐘數量或間隔寫成 Threads 官方保證安全的值。
2. READ 出現限制操作頻率、稍後再試、登入或驗證阻擋時，讀取實際提示與時間，停止受影響的發送，不連按、不換帳號繞過；已取得的資料整理與其他不受影響的工作可繼續。
3. WRITE 保存停止位置、已開始但未證實的動作，以及恢復操作前需核對的條件；依平台畫面指示恢復，不自行宣告冷卻時間已滿。
4. READ 恢復或下一輪開始時，先查已開始動作的實際結果；只有回讀確定未送出，才可重新開始同一動作。

### Phase 6 -- 保存本輪結果與交接

1. WRITE 保存已回覆、邀請送出、進入 Discord、申請與審查結果各自的證據、時間、未完成事項及下一步；已加入者仍可有新的客服問題，不能因一個「完成」就永遠跳過該帳號。
2. WRITE 共享 repo 只保存工作流及適合公開的資訊；私人對話、聯絡資料與逐人處理紀錄依有權限的保存位置維護，不直接貼進這個公開 repo。
3. WRITE 將成功處理、未確認的發送、平台阻擋、尚未讀到的範圍及需要拍板的事項交接給本輪拍板的人與後續執行者；只釋放自己持有的鎖，不把未完成結果改成成功。

# Note

## 尚未聊清楚或未確認的部分

| 項目 | 目前如何處理 |
|---|---|
| 可使用的 Discord 邀請、目的地及邀請權限 | 執行前核對；本 SOP 不提供或猜測有效連結 |
| 申請提交入口與審查程序的實際設定 | 依已有公開規格；未設定或無法確認的部分保留，不假定已上線 |
| 誰審自介、基本參與度的具體標準 | 依[申請制度](../01-制度/[機制]申請制度.md#尚未決定事項)及[成員參與制度](../01-制度/[機制]成員參與制度.md#尚未決定事項)的未決事項，不由客服補定 |
| 私人處理紀錄的保存位置、可存取者及跨執行者交接方式 | 尚未在此 repo 定義；不得以公開 specs 或 logs 暫存私人內容 |
| 邀請後未加入的提醒次數、間隔與具體客服話術 | 尚未拍板；不反覆主動催促，可接續對方新問題 |
| 使用 AI 操作 Discord 的具體工具與逐步點擊方式 | 依當輪可用工具實測；本 SOP 不把舊 LINE 選好友測試當作 Discord 已測通 |

目前既有操作試跑只涵蓋 Threads 的原串、留言、續串、收件匣、陌生訊息與私訊草稿；舊 LINE 邀請入口的觀察已不作為現行招募目的地。Discord 邀請、自介審查及整段招募完成的實際驗證，需分別留下新證據。
