# Threads 引流招募客服 SOP

# Problem

每位負責人可能使用不同帳號發起招募，詢問也會散在不同貼文、留言與私訊。若流程綁定特定貼文或個人，其他人就難以接續；同一人出現在多處時，也容易漏回或重複邀請。這份 SOP 提供共同處理方式，減少[加入申請的處理成本](./[機制]志工協作與開源知識.md#我們能不能減少我們的營運成本)。

# Specs

## 處理範圍

適用於任何透過 Threads 發起招募、回覆留言或處理加入詢問的人。可以從新貼文開始，也可以接續既有對話，不限定特定帳號、貼文或發文時間。

本組織目前使用 Discord，加入方式依[申請制度](../01-制度/[機制]申請制度.md)；執行前確認最新安排。

## 開始前

確認本次使用的帳號、處理範圍、負責人與拍板的人，以及可用的邀請和申請入口。指定本次使用的私人邀請帳號 truth，先看已有紀錄，避免多人同時處理同一人。只整理或試跑時，不接受陌生訊息、不發訊息或邀請。

新發起招募時，先在貼文說明目的、參與方式及聯絡管道；收到留言或私訊後，依下列步驟處理。若是接手他人的招募，先了解貼文內容與先前回覆。

## SOP

1. **看完整對話。** 查看新留言、續串、必要圖片，以及收件匣、陌生訊息和隱藏訊息，了解對方在問什麼。

2. **確認有沒有處理過。** 以完整 Threads 帳號核對本次的私人邀請帳號 truth、其他可存取紀錄，以及自己或其他負責人的最新回覆，合併同一人的不同來源。曾答應邀請不等於已發送；送出結果不明時，先查看實際對話，確認前不重送。

   例子：你發起招募後，同一人先留言「想加入」，又傳來私訊。另一位負責人已回覆「稍後提供加入方式」，但未確認是否已發送邀請。先把兩個來源合併，查對話與紀錄；確定沒發過，再接續邀請。

3. **回答問題，確認加入意願。** 依現行制度回答，優先接續既有私訊。只表達支持或被別人標記，不代表同意加入；先問本人。遇到尚未決定的規定，記下問題，交給拍板的人確認。

4. **提供邀請與加入說明。** 本人願意參與後，再看一次最新對話，核對收件人、內容、既有邀請及有效入口，確認沒有其他人已處理。記下準備發送的動作，再提供目前社群的邀請與申請說明。同名或同頭像不能當作跨平台身分證據，須由本人確認。沒有有效入口時先保留待確認；不要自行建群、核准申請或授予權限。

   **Payload（公版訊息）**

   傳送前補齊下列閱讀文件、自介範例及活動的連結，並確認邀請可用；不要把待補文字一起傳出。將下方公版訊息全文一次複製貼上到該對象的私訊訊息區，確認收件人及內容無誤後送出。

6. **更新紀錄，交接未完成事項。** 回讀確認公版私訊邀請已送出後，將 Threads 帳號加入本次的私人邀請帳號 truth，同時記下送出時間、私訊證據及記錄者。帳號去除 `@` 並轉小寫，同一帳號只記一筆已送出邀請；結果不明時先回讀確認，不記為已送出，也不重送。另記下問題、來源連結、已做的事與下一步。尚未讀到的範圍或無法確認的結果也要記錄，交接給本輪拍板的人與後續負責人。

## 注意事項

- 同一邀請不要重複發送；對方有新問題仍可回覆。本人拒絕或要求停止聯絡時，停止主動邀請。
- 分批處理，避免短時間大量貼相同內容。遇到頻率限制、登入或驗證阻擋，停止受影響的發送，記下停止位置；恢復前先確認先前動作的結果，不連按或換帳號繞過。
- 私人對話、聯絡資料及逐人處理紀錄存放在有權限的位置，不貼進公開 repo；邀請連結也不要未經確認就公開。
