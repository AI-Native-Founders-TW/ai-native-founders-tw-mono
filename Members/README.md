# 自我介紹與 PR 提交說明

加入方式依[申請制度](../specs/01-制度/[機制]申請制度.md)。提交自介 PR 是加入的基礎門檻；審查通過後才成為成員。Discord 邀請、Star 及活動留言不取代自介審查。

## 自介參考範例

下方格式可自由調整。請寫清楚你是誰、為什麼加入、想要獲得什麼、想分享什麼，以及自己的 R&R（Role and Responsibility）：可以幫什麼忙、想要幫什麼忙。

自介看的是參與真誠，不看背景、實力或經歷。沒有專案、仍在探索創業志向，也可以如實說明。R&R 必須在提交前寫清楚，不能留待之後補充；寫得越清楚，未來大家有志辦活動時，越能善用 AI 找到相關可以幫忙的志工。這不表示承諾接受任何指定工作。

```markdown
# <你的名字或慣用稱呼>

## 我是誰

<介紹目前在做什麼、關注什麼。正在創業、做產品、工作、就學或仍在探索，都可以如實寫。>

GitHub：<你的 GitHub 帳號>
其他聯絡方式或作品連結：<填寫你願意公開的聯絡方式或作品連結，選填。>

## 為什麼想加入

<是什麼讓你想加入這個組織？可以從最近遇到的問題、一次經驗，或想嘗試的事情說起。如果還不確定自己的創業志向，也可以說明目前想探索什麼。>

## 想要獲得什麼

<你目前最想釐清什麼問題、學到什麼，或認識能交流哪些事情的人？請盡量具體，讓大家知道可以跟你聊什麼、在哪裡提供協助。>

## 想分享什麼

<有哪些經驗、故事、知識、做法或正在嘗試的事情，願意和大家分享？尚未有完整成果也可以如實寫。>

## 我的 R&R：可以幫什麼忙、想要幫什麼忙

R&R 必須在提交前寫清楚，不能留待之後補充。寫得越清楚越好：未來大家有志要辦任何活動，都可以善用 AI，透過 R&R 尋找相關可以幫忙的志工。

### 可以幫什麼忙

<具體寫出你目前可以協助的事情，以及能協助到什麼程度，讓發起活動的人與 AI 知道哪些事情可以找你。>

### 想要幫什麼忙

<具體寫出你有意願參與哪些活動或工作、想協助哪個部分。可以是你想一起嘗試或邊做邊學的事情，請說明清楚。>
```

## 提交 PR

1. 登入 GitHub，Fork [本 Repo](https://github.com/AI-Native-Founders-TW/ai-native-founders-tw-mono)。
2. 在自己的 Fork 建立分支，在 `Members/` 新增一份 Markdown 自介。檔名可參考 `<你的 GitHub 帳號>.md`；這是方便辨識的建議，不是固定格式或資格條件。不要修改別人的自介。
3. 將範例中的 `<...>` 替換成自己的內容。可以用 AI 協助整理，但提交前務必由本人親自 review 全文：確認經歷、連結、動機、期待與 R&R 真實，沒有 AI 編造的內容或參與承諾，也沒有不願公開的個資。
4. Commit 變更後，從自己的分支開啟 Pull Request，目標為本 Repo 的 `main`。確認變更只有自己的自介，再按 **Create pull request**。可參考 [GitHub 官方 PR 說明](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request-from-a-fork)。
5. PR 是申請，審查通過後才成為成員。若需要補充，依 PR 上的審查意見修正。有不熟悉的操作或問題，可以在 Discord 中發問或回覆。

審查依現行[申請制度](../specs/01-制度/[機制]申請制度.md)辦理，執行安排見[自介審查](../specs/01-制度/[機制]自介審查.md)。尚未決定的審查人、程序及平台權限，不在此自行設定或承諾處理時間。
