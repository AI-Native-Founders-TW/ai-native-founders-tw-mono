# AI-Native Global Founders Speedrun Taiwan

用一份筆記槓桿全台創業者的認知。我們透過共學、交流與協作，收集創業與出海經驗，整理成可持續使用的開源知識、攻略與流派，讓更多臺灣創業者理解自己的選擇，並培養出海創業的能力。詳見[願景](specs/00-願景和問題/vision.md)。

## Quick Start

把下面的 prompt 貼給你的 agent。第一次先取得 repo；已經 clone 的人，可以直接在 repo 中選擇想做的事，將 `〈…〉` 換成自己的內容。

### 先 clone，認識這個組織

```text
請 clone https://github.com/AI-Native-Founders-TW/ai-native-founders-tw-mono.git，並進入 repo；如果本機已有這份 repo，就使用既有目錄，保留未提交的修改。

先讀 AGENTS.md、FORMULATION.md、specs/00-願景和問題/vision.md 與 specs/01-制度/憲法.md，再看 members/README.md 及 specs/02-R&R/README.md。
請簡單說明這個組織想做什麼、我可以如何加入及參與，並問我想從哪件事開始。現行規則以 specs 為準，不把歷史討論、候選人名或規格文件當成已完成的任命與平台設定。
```

以下 prompts 都在這份 repo 中執行，請 agent 先遵循 [AGENTS.md](AGENTS.md) 與 [FORMULATION.md](FORMULATION.md)，再依任務讀取相關文件。

### 我想了解組織怎麼運作：誰負責、誰能決定、如何參與

```text
請帶我理解這個組織的運作方式，不要只列文件名稱或把整份制度貼給我。

先讀 AGENTS.md、FORMULATION.md、憲法、憲政制度、specs/02-R&R/README.md、members 的成員與 assignment 資料，以及 specs/05-社群基建/ 的權限規格；需要說明具體操作時，再讀對應 SOP。請用清楚的中文，依序解釋：

1. 組織的目的，以及憲法、制度、R&R、SOP 各自負責什麼。
2. 正式成員、Contributors、Leader 與 Council 的關係；如何加入、選擇分工，以及誰負責哪些事情。
3. 哪些事可以自行做、哪些由 Role Leader 決定、哪些需要共同表決；用辦活動、修改網站、調整分工等實際情境說明。
4. 組織決策權與 GitHub／Discord 平台權限如何區分，權限如何取得、交接與撤回；不要把持有管理帳號當成具有全部決策權。
5. 成員如何提出建議、參與表決、提出異議、要求更換 Leader，或修改制度與憲法。

每個重點附上對應文件或章節，讓我能繼續閱讀。需要提到門檻、期限或例外時，先核對現行條文，不憑印象簡化。

最後分清楚：制度已經規定什麼、目前有哪些有效人員與可核對的實際配置，以及哪些仍待確認。沒有查證平台設定時，不宣稱權限已開通；歷史會議的認領也不當成有效任命。

先給我一份能掌握全貌的說明，再一次問我一個問題，帶我深入最想了解的部分。
```

### 我想提交自我介紹，申請加入

```text
請用引導式訪談協助我撰寫自我介紹並提交加入申請。從 members/README.md 開始，沿文件引用閱讀相關制度與 SOP，再依要求安排訪談、落檔與提交。

一次只問一個問題。每次收到答案，就忠於我的原意，逐步整理成清楚、連貫的中文並更新草稿，再問下一題；已有答案不重問，不編造經歷或承諾。

完成前，依組織目標與 SOP review coverage：自介是否充分說明我的動機、背景、想如何參與，以及我對基本義務的理解與接受。缺少的內容繼續逐題引導，不把背景或經歷變成額外門檻。

最後讓我確認全文與公開內容，再依 SOP 寫入指定位置並提交 PR，回報實際結果與下一步；不代替正式審查。
```

### 我想參與分工，找一件可以做的事

```text
我想參與的方向是：〈感興趣的事情、可以幫忙的部分與可投入時間〉。

請讀 specs/02-R&R/README.md、相關 Role 與 members/r-and-r-assignment.md，幫我找到適合的分工、現任聯繫者及相關 SOP。人選待確認或職位空缺時請如實說明。

若我要調整 Contributors，依 specs/03-SOP/憲政/ 中的加入退出或調整 Contributors 分工 SOP，同步準備我的兩表資料。若我想承接具體工作，先找既有 Issue 或 Plan，幫我整理可接續的工作與完成條件，再由我確認承接範圍。
```

### 我有提議，想找人一起討論

```text
我的想法是：〈想做的事、遇到的問題，以及希望大家幫什麼忙〉。

請依 specs/03-SOP/[SOP]提出提議或活動與號召討論.md，先查看有沒有相關 Issue 或既有 Plan，協助我整理成容易回應的討論內容。不需要先把整套方案想完，也不要每次都新增 Plan。

請提供適合的 Issue 標題、正文及可接續的 R&R，讓我確認後再發布。若涉及共同決定，說明應接哪份 SOP；不要把一般討論當成正式表決。
```

### 我想辦一場活動

```text
我想辦：〈活動想法、適合對象、預計時間或目前未定的部分〉。

請讀 specs/02-R&R/[Role]活動籌辦與協助.md 與 specs/03-SOP/[SOP]活動籌備、舉辦與會後整理.md，協助我釐清目的、召集人、需要的協助與下一步。

資料未確定時先協助號召討論；確定籌辦後，準備流程、分工與 Discord events forum 公告，並安排會後摘要及知識整理。需要共同資源或對外合作時，依制度接續決定；沒有接受工作的人不要寫成已承接。

對外發布或聯繫前，先讓我確認內容與對象。
```

### 我想邀請受訪者，或整理一份創業知識

```text
我想理解的問題或已有的素材是：〈問題、受訪者人選、筆記或資料來源〉。

請讀 specs/02-R&R/[Role]受訪者邀請與經驗分享.md 與 specs/02-R&R/[Role]開源創業知識及流派整理.md，判斷現在需要取得經驗，還是可以開始整理。

需要邀請時，幫我整理人選依據、邀請草稿、分享問題與下游交接安排，先讓我確認再聯繫。已有素材時，先確認來源、可使用與公開範圍、署名及是否需要本人確認，再整理情境、判斷、行動、結果與限制。

分享不一定要辦活動；邀請答應也不等於完成。請明確列出已取得的資料、尚待確認的部分，以及誰已接受後續整理。
```

### 我想修改網站或其他系統

```text
我想改進：〈使用情境、目前問題與預期行為〉。

請讀 specs/02-R&R/[Role]Hacker.md、相關 specs、既有 Plan 與 modules/README.md，先釐清規格和實作的差異，沿用適合的既有工作紀錄。

需要修改網站時，依 modules/README.md 初始化對應 submodule，再讀該 repo 的 AGENTS 或 CLAUDE。完成實作與適當檢查，說明相關規格、實作及版本之間的關係。不要把本機完成當成已部署；部署前先提供可 review 的結果及所需安排。
```

### 我想提出制度修改或請求覆核

```text
我遇到的情況或想改的制度是：〈具體事實、原決定或希望改變的內容〉。

請讀 specs/03-SOP/憲政/README.md，找到適用 SOP，再核對憲法與憲政制度。幫我區分一般討論、正式提案與覆核，整理需要的事實、依據及下一步。

先協助我準備案件內容；不要把我的提案寫成已通過的規則，也不要代替有權人員裁決或投票。
```
